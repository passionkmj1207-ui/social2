# 블로그 글쓰기 지침 (v3) — 월급노트

작가 단계에서 따르고, 수치검증 단계가 검수 기준으로 삼는 문서다.

## A. 목적과 독자
- 한 글에는 하나의 통념(또는 논쟁)만 다룬다. 독자가 커뮤니티·뉴스에서 마주치는 불안과 선택의 고민을 소재로 삼는다.
- 독자가 얻어 가는 것은 **"내 상황을 판단할 새 기준"** 하나다.
- 유형은 둘 중 고른다(섞어도 된다).
  - **A형 데이터 반전형**: 통념을 통계로 뒤집는다.
  - **B형 큐레이션 해설형**: 화제의 글·주장을 요약 → 팩트체크 → 반응까지 모은다.

## B. 제목
- 공식에 끼워 맞추지 않는다. **글 전체를 관통하는 핵심 키워드**로 구성한다.
- 읽는 순간 "왜?", "결국 뭔데?"가 떠오르는 **호기심 문장**이어야 한다.
- 방법(공식 아님): 문장을 끝맺지 않고 결말 숨기기 / 통념과 반대되는 결론 암시 / 키워드 + 반전 / 독자가 속으로 하던 질문 던지기.
- 본문이 답하지 못하는 호기심은 만들지 않는다. 후보 3개 이상 → 1개 선택.

## C. 본문 구조: 도입 → 본론 → 반대 측면 → 결론
틀은 고정하고 세부 구성과 분량은 주제에 맞게 조정한다.

1. **도입**: 일반 명제/현상 → 기준 수치 또는 화제 사례 1개 → **핵심 질문(볼드)** → 예고 문장("~를 함께 알아보자").
2. **본론**: 핵심 질문에 근거로 답한다.
   - A형: 공식 통계 → 현실 보정(기준이 다른 수치 환산) → 직접 계산한 체감 수치.
   - B형: 원글 요약 → 번호 정리(①②③) → 항목별 사실 점검 → 핵심 수치 계산/표.
   - 구간이 3개 이상이면 큰 소제목(`###`)으로 나눈다. 질문형·명사형 모두 가능.
3. **반대 측면**: 본론 결론을 약하게 만드는 사실·비용·리스크·예외를 최소 한 문단 공정하게 다룬다. 다른 사람의 목소리(반박, 댓글)로 제시해도 된다.
4. **결론**: 핵심 질문의 답을 한 줄로 단정(빨간색) → 단서와 제언 → 독자에게 묻는 질문(가능하면 양자택일) + "여러분의 생각이 궁금합니다".

## D. 읽기 편한 글의 장치
1. 자문자답 리듬: 질문 → 한 단어 답 → 수치.
2. 독자 대신 묻기: 독자가 속으로 하던 말을 인용부호로 꺼낸다(빨간색 가능).
3. 동행 어투: "함께 알아보자", "따져봐야 한다", "계산해 봐야 할 것 같다".
4. 독자 시간 배려: 원문이 길면 "글이 길어서 이유만 추리면 N가지다".
5. 주장과 사실 분리: 주장을 소개하면 바로 근거 유무를 한 줄로 점검한다.
6. 간접 화법: 남의 주장은 "~라고 한다", "~는 입장이다".
7. 수치의 한계 동시 제시: "이 수치가 말하지 않는 것"을 한 줄 붙인다.
8. 독자용 계산 확장: 표·공식으로 독자가 자기 숫자를 대입해 볼 수 있게 한다.

## E. 표·각주
- 표는 가정 3개 안팎. 각주에 가정과 한계를 밝힌다(`※ 세전 단순 계산…`).
- 표 뒤 문단에서 표가 말해 주지 않는 것을 짚는다.

## F. 숫자 규칙 (수치검증 단계의 검수 대상)
- 핵심 수치는 글 전체 5~7개(많아도 8개)로 제한한다.
- 수치마다 **출처 기관명 + 기준 시점**을 쓴다.
- 수치 뒤에 쉬운 말 풀이를 붙인다.
- 직접 계산한 값은 계산식과 가정을 밝히고, `claims.json`에 `type: calculated`와 `formula`를 기록한다.
- 기준이 다른 통계를 비교할 때는 보정 설명을 넣는다.
- **기억·추정으로 숫자를 채우지 않는다.** 원출처에서 확인한 값만 쓴다.

## G. 문체와 서식 표기
- 기사체 "~다", 가끔 "~듯하다", "~싶다". 문단은 2~4문장, 문단당 메시지 1개.
- 분량은 공백 포함 1,500~2,500자 기준.
- **강조 3종 표기** (네이버 에디터에 옮길 때 서식으로 변환)
  - `==텍스트==` → 노란 형광펜: 핵심 수치·근거 (글 전체 4~6곳)
  - `[빨강: 텍스트]` → 빨간색: 독자 대신 묻는 말, 결론, 고른 인용 소개 (2~3곳)
  - `**텍스트**` → 볼드: 질문, 주장, 번호 소제목 (2~3곳 + 번호 항목)
- 한 문단에 강조는 최대 1곳.
- 차트 이미지는 `charts.json`의 anchor 문단 뒤에 자동 삽입된다. 본문에 이미지 문법을 직접 쓰지 않는다.

## H. 톤과 태도
- 선동·훈계 금지. 데이터가 말하게 한다. 글쓴이 의견은 결론·제언에만 둔다.
- 인용한 사례·인물을 조롱하지 않는다.
- 결론은 "~다"로 단정하되 바로 뒤에 한계·단서를 붙인다.
- 어느 쪽이 정답이라고 몰아가지 않는다. 투자·매매 권유 문구를 쓰지 않고, 글 끝에 정보 제공 목적 고지를 넣는다.
- 정치적 사안은 발언·사실만 전하고 해석을 붙이지 않는다.

## I. 인용·캡처·개인정보
- 커뮤니티 글·댓글은 **요약이 기본**. 원문 인용은 짧게, 필요한 부분만.
- 닉네임, 회사명 등 식별 정보는 쓰지 않는다. 캡처를 쓸 때는 가린다.
- 기사·보고서 문장을 그대로 옮기지 않는다. 수치와 사실만 가져와 자기 문장으로 쓴다.

## J. 출고 체크리스트
- [ ] 제목이 핵심 키워드에서 나왔고 본문이 그 호기심에 답하는가
- [ ] 도입·본론·반대 측면·결론이 모두 있는가
- [ ] 도입에 핵심 질문과 예고 문장이 있는가
- [ ] 남의 주장을 소개한 뒤 근거 유무를 바로 점검했는가
- [ ] 모든 수치가 `claims.json`에 있고 검증을 통과했는가
- [ ] 수치·표 뒤에 "말해 주지 않는 것"을 한 줄 이상 짚었는가
- [ ] 반대 측면을 한 문단 이상 공정하게 다뤘는가
- [ ] 결론이 핵심 질문에 직접 답하는가
- [ ] 마지막이 독자에게 묻는 질문인가
- [ ] 강조가 3종 규칙을 지켰는가
- [ ] 식별 정보와 투자 권유 문구가 없는가
